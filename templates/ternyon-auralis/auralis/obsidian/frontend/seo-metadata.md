# SEO & Metadata

## Site config

`src/lib/site.ts` (`siteConfig`) is the **single source of truth** for SEO —
name, description, origin URL, Twitter handle, theme colour. The metadata
generator, `robots.ts`, `sitemap.ts`, the JSON-LD helper **and the generated
share card** all read from it, so the name and positioning line on the card can
never drift from the ones in the `<head>`.

Filled in for this project: **Auralis**, with the studio's positioning line as
the description and `#000000` as the theme colour (the black the scene and the
preloader sit on). There is no longer an `ogImage` field — the card is generated
(below).

`siteConfig.url` comes from `NEXT_PUBLIC_SITE_URL` (see [[environment-variables]]),
falling back to `http://localhost:3000`. ⚠️ `.env` still ships the starter's
`https://example.com`; set the real origin before launch or every canonical, OG
and sitemap URL points at the placeholder.

## Icons & share card — generated from the brand mark

No hand-made PNGs. Three **file-based metadata** routes render at build time via
`ImageResponse`, and Next discovers and wires them itself:

| file | route | what |
|---|---|---|
| `src/app/icon.tsx` | `/icon` | 64² favicon |
| `src/app/apple-icon.tsx` | `/apple-icon` | 180² home-screen tile |
| `src/app/opengraph-image.tsx` | `/opengraph-image` | 1200×630 share card (also the Twitter image — with no `twitter-image.tsx`, Next points the card at this route) |

All three draw the **mark** — the scene's glyph, two crossed bars, proportioned
from `sceneConfig.glyph` so the tab icon and the 3D hero are the same shape. It
is drawn as two rotated rules rather than imported from
`public/assets/brand/logo.svg` (kept as the canonical artwork) because Satori,
what `ImageResponse` renders with, doesn't rasterise external SVG files. The card
also loads the site's own display face from `src/app/fonts/`.

> [!warning] Don't declare `icons` or `openGraph.images` in `generateMetadata`
> Paths listed there **override** the generated routes. `generateMetadata` now
> omits both by default; `ogImage` remains only as an explicit per-page override.
> For the same reason `src/app/favicon.ico` was removed — an `app/favicon.ico`
> takes precedence over `app/icon.tsx`. The starter's placeholder icon set
> (`public/favicon*`, `android-icon-*`, `apple-icon-180x180`, `open-graph.png`,
> `browserconfig.xml`) was deleted with it; `manifest.json` now points at `/icon`
> and `/apple-icon`.

## Metadata generator

`src/utils/seo/generate-page-metadata.ts` exports two builders:

```ts
import {
  generateMetadata,
  generateViewport,
} from "@/utils/seo/generate-page-metadata";

export const metadata = generateMetadata({ title: "…", description: "…" });
export const viewport = generateViewport();
```

- `generateMetadata(props?)` → a Next.js `Metadata` object: title/description,
  OpenGraph, Twitter cards, canonical, icons, robots. `metadataBase` is **always
  set** from `siteConfig.url`, so relative URLs (OG image, canonical) resolve to
  absolute — required by social scrapers.
- `generateViewport()` → the `Viewport` export. `themeColor` lives here, **not**
  on the metadata object (Next deprecated it there).

Accepted `generateMetadata` options: `title`, `description`, `url`, `ogImage`,
`twitterHandle`, `author`, `siteName`. (`keywords` and the non-standard `other`
tags were dropped — no SEO value.) `ogImage` is an **override only** — leave it
unset so the generated card wins; the `icons` block is gone for the same reason.

## robots.txt & sitemap.xml

Generated by the Next file conventions:
- `src/app/robots.ts` → `/robots.txt` — allows all crawlers, points at the sitemap.
- `src/app/sitemap.ts` → `/sitemap.xml` — lists public routes (home only so far;
  add an entry per route as the site grows).

## Structured data (JSON-LD)

`src/utils/seo/structured-data.ts` → `getSiteStructuredData()` builds an
`Organization` + `WebSite` JSON-LD graph. The root layout renders it once in a
`<script type="application/ld+json">`.

## Bot detection

`src/utils/is-bot.ts` exports `isBot()` — a **server-only** async helper that
reads the `user-agent` header and returns `true` for Lighthouse, Googlebot,
PageSpeed, HeadlessChrome, GTmetrix, Pingdom, Bingbot, Yandexbot.

> [!caution]
> Calling `isBot()` (or any `headers()` reader) in a route **opts it out of
> static prerendering** — a TTFB cost for every visitor. Serving crawler-specific
> behaviour also borders on cloaking. Prefer the [[animation-system|reduced-motion]]
> path (`<ReducedMotion>`): animations only touch opacity/transform, so content
> is always in the DOM and crawlers see it regardless. Use `isBot()` sparingly.

## Static assets

The `public/` **root** now holds only `manifest.json` — the icons and the share
card are generated routes, not files (see above). Brand artwork lives at
`public/assets/brand/logo.svg`; other site **content** assets (images, videos) go
under `public/assets/<section>/` — see [[folder-structure]].
